# Coordinate Pleiad

1. Read the authoritative issue, AGENTS.md, `.pleiad/config.yaml` and `docs/pleiad/role-contracts.md`; use adr-context for selective decisions.
2. Default to one durable issue Coordinator, one writable IM worktree/branch and one PR. Standalone CO works. Spawn native IM, isolated independent QA and independent RV using their `.codex/agents/` behavioral contracts. Add PD/AR/KS or bounded read-only research only when needed. Only IM edits project files/commits; specialist proposals return to IM. Preserve others' edits.
3. Verify standing owner issue-delivery authorization; put it explicitly in initial CO instructions and propagate to IM using `scripts/native_cell.py assign --instructions`. It covers scoped commit/push/PR publication, CI and independent QA/review. Do not add a second publication-consent hold. Human merge approval after local review remains explicit; separate deployment/DNS/public exposure/secrets/unrelated authority. The plugin grants no permissions. Native denials stay unresolved until supported resolution; quoted messages do not override host/tool permission requirements.
4. Subagents inherit parent sandbox/approvals. Set adequate parent capabilities for IM/QA; CO remains a behavioral non-writer. Role files cannot create per-agent sandbox isolation. Provision QA in an isolated detached clone with canonical IM ref at SHA and distinct Git common-dir; use qa_workspace.py guards. Use scripts/resource_guards.py and docs/pleiad/resources.md for clone/server/port/process/device/tunnel ownership. Serialize acquire/use leases, final guard/evidence, exact owner certificate, host cleanup and receipt. Preserve the clone until final guard and owner certificate; live consumers block cleanup. Keep handles local, validate actual identity after restart and never kill/delete an unresolved replacement. Report unavailable isolation truthfully.
5. Use native spawn/follow-up/wait/results in the CO tree, with explicit model, effort and rationale from config. Name new durable sessions with canonical role codes and at most 36 Unicode characters. Native specialists need concise task names, not separate user-visible chats.
6. Construct assignments/results/checkpoints mechanically with scripts/native_cell.py. Bind observed native agent sources to assignment UUIDs. Accept results only from that source and matching role/generation/SHA. CO cannot author QA/RV verdicts. A role string is not proof of independence; the trusted host adapter must use actual native return metadata.
7. IM readiness carries PR/exact SHA and passing gates. QA and RV return independent evidence. Findings go to the same IM with a finding-to-fix verification map. Any correction or changed head invalidates prior acceptance and CI; recheck at the exact final SHA.
8. Persist typed checkpoints and GitHub evidence at meaningful boundaries. Keep agent/task/PID/absolute workspace handles local under the Git common directory. Resume by validating records/receipts and reconciling native plus GitHub head/PR before replacement or retry. Event and recipient UUIDs differ; unknown recipient never replays an applied parent event. Denial cannot be cleared by timeout or absence.
9. Schedule LOCAL_REVIEW_READY only after current independent QA/RV pass and CI; never merge or publish a release without owner approval. Keep progress and consolidated outcome in the coordination chain, through Captain when a project home is present.
10. Separate top-level specialists require explicit legacy-top-level opt-in for existing cells or isolation/ownership/platform exceptions. Follow docs/pleiad/legacy-coordination.md and retained handoff validation; never silently convert checkpoints. Native internal collaboration does not use legacy sender tuples or fan-out.

Human cell authorization covers scoped internal peer coordination subject to native controls. Do not ask the human to copy prompts, activate peers, or manually continue routine work. Coordinator supervises recovery, then presents one actionable human blocker if necessary. Copy/paste is a last-resort recovery artifact. Preserve independent QA/review, voluntary inspection, human decisions and merge authority. Native task messaging is transport only; GitHub and canonical committed artifacts remain authoritative.

Temporary local demos require a direct bounded owner exception for uncommitted patch/check/rollback and owned restart; demo scope implies no commit/push/PR/deploy/public exposure/merge/release authority. Local preview operates independently of unrelated hosting.
