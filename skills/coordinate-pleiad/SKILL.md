# Coordinate Pleiad

Read the authoritative issue, applicable `AGENTS.md`, `.pleiad/config.yaml`, and `.codex/agents/coordinator.toml`; use adr-context for selective decisions. Before dispatch or recovery, read the installed `docs/pleiad/` [role contracts](../bootstrap-pleiad/assets/repository/docs/pleiad/role-contracts.md), [coordination lifecycle](../bootstrap-pleiad/assets/repository/docs/pleiad/coordination.md), and [resource procedure](../bootstrap-pleiad/assets/repository/docs/pleiad/resources.md). These are mandatory policy discovery, not optional background. Use repository-installed procedures as authority; the links locate packaged copies for adoption.

Standalone CO is supported: one issue, one durable CO, one sole IM writer/worktree/branch, one PR, native independent isolated QA and RV. CO supervises and reports progress; it cannot write project files or author specialist verdicts. Read each assigned role's `.codex/agents/` contract. Use native spawn/follow-up/wait/results with explicit model, effort and rationale from config, and `scripts/native_cell.py` plus `.pleiad/native-cell.schema.json` for typed boundaries and observed source binding. Keep local handles under Git common-dir and public evidence sanitized.

Verify standing owner commit/push/PR/CI/QA/review authorization in initial CO instructions and propagate it explicitly with `assign --instructions` to IM. No extra publication-consent hold. Human merge approval remains explicit; deployment, DNS, public exposure, secrets and unrelated publication require separate authority. Subagents inherit parent sandbox/approvals; the plugin grants no permissions. Preserve native denials until supported resolution.

Follow the lifecycle for exact-SHA evidence, same-IM corrections, changed-head invalidation, and uncertain delivery reconciliation before retry/replacement. LOCAL_REVIEW_READY requires current independent QA/RV and CI. Follow resources for isolated QA provisioning, consumer leases, final guard, owner certificate and host cleanup; never clean active or unresolved resources. Temporary demos need direct bounded owner scope and uncommitted patch/check/rollback, with no implied publication authority.

When a persistent project home is used, read the installed [Captain procedure](../bootstrap-pleiad/assets/repository/docs/pleiad/captain.md); outcomes stay in that coordination chain. For existing legacy cells or explicit isolation/ownership/platform exceptions only, require `legacy-top-level` opt-in and read the installed [legacy procedure](../bootstrap-pleiad/assets/repository/docs/pleiad/legacy-coordination.md). Preserve existing checkpoints and applied events; never silently convert them. CO handles safe recovery before an actionable human blocker; routine delivery must not depend on human prompt relaying.
