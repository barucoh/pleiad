# Captain project supervision

Captain (CP) is the persistent project home for a human-authorized queue of issues. It supervises durable issue Coordinators (CO) through supported cross-session task control; each CO owns its native specialist tree. Standalone CO remains supported. CP never implements, commits, authors specialist verdicts, merges or creates integration branches. Existing project home titles remain stable; new issue-specific CP/CO sessions use the configured canonical role code and 36-character limit. Both CP and CO conservatively default to gpt-6-astra/Medium; High requires an explicit risk rationale.

## Queue and admission

`scripts/captain_queue.py` and `.pleiad/captain-queue.schema.json` implement a portable project checkpoint. One serialized Captain owns mutations; concurrent queue writers are unsupported. Start with `init --repository owner/repo --cap 2`, using the positive `captain_concurrency_cap` from config or an explicit owner setting. Import each authoritative issue using `enqueue --spec <json>`; fields are `issue_number`, `title`, `ownership_paths`, `dependencies`, `priority`, `issue_state`, and `evidence_urls`. Dependencies are `{issue_number, requires}` records. `requires: closed` is the normal gate; `local_review_ready` permits an explicitly authorized unmerged review stack. Local review does not imply merge/closure. Missing dependencies and cycles block admission.

Declare canonical repository-relative writable paths, not globs; `.` owns the entire repository. Ancestor/descendant paths overlap. Ownership includes shared generated files and metadata when IM will edit them. Independent worktrees alone do not make overlapping writes safe. Unknown/failed activation and blocked live cells retain capacity and ownership until reconciled; issue closure alone never releases a running CO. Local-review-ready cells release only after CO certifies it is quiescent. Closed/cancelled records never redispatch automatically. Reopening, cancellation or changed ownership requires explicit issue/CO reconciliation; do not delete queue history to bypass it.

`actions` identifies a concrete next action/blocker per cell. `reserve --issue <n> --objective <text>` rechecks admission and records a stable assignment UUID plus a separate unknown activation-attempt UUID before external dispatch. It fails on a duplicate issue assignment, cap exhaustion, unmet dependency or ownership overlap. A list of ready candidates is advisory: reserve each sequentially before dispatch so the next candidate sees the new lease. Save every subsequent meaningful boundary before another effect.

## Durable CO activation and local transport

Generate `instructions --issue <n>` and create a durable CO using the host's supported task control (a native specialist spawn is not a durable CO). Initial instructions explicitly include verified standing owner authority for scoped commit/push/PR publication and CI/independent QA/review, and scoped CP/CO messaging authorization. No extra publication hold is permitted. These statements neither grant platform permission nor reopen a native denial. Human project authorization must actually cover the queued issues and internal messages; a queue entry alone is not consent. CO propagates standing authority to IM through `native_cell.py`.

The Python library exposes `new_local`, `bind`, `reconcile`, `attempt`, `progress`, `recover`, and `rehydrate` for the trusted host adapter. The CLI covers pure queue construction, reservation and instruction generation; no function performs network/task transport. Read and persist adapter state separately at `local_path(repository, project_id)` under the Git common directory. It stores host-observed CP/CO source handles, assignment-context digests, progress/transport receipts and retired sources. Never commit or publish that state. Payload role names and manually invented source strings are not identity proof; use actual create/read/wait return metadata.

After a successful create, `bind` the observed CO handle, then `reconcile` the exact activation attempt as applied with durable issue/PR evidence. An incomplete/timeout create remains unknown. A failed create remains failed until fresh exact-attempt observations establish applied or absent; an error message does not prove no task was created. Search/read existing tasks and durable issue/CO evidence before retry. If absent, `attempt(..., kind="activate")` records a new recipient attempt for the same logical assignment. Applied activation cannot repeat. A resend also needs a persisted `attempt(..., kind="continue")` and exact-attempt reconciliation. Unknown/failed sends prohibit other sends/replacement, even if an earlier lifecycle result is already applied. Do not replay that parent lifecycle result.

`recover` requires proven stopped/lost old execution, reconciled transports, unblocked authority, durable evidence and an existing observed binding. It retires the local source, retains issue/cell/PR identity and advances the execution generation before recording a replacement intent. Bind only the actual replacement source and reconcile its activation. Rehydrate the original cell rather than starting another IM/worktree/PR. Native denial is resolved through supported controls; timeout, absence or replacement never clears it.

## Active supervision and exact-head readiness

Bound CO updates enter through `progress`, with its native cell checkpoint/receipts, freshly observed SHA/PR, evidence, concrete `next_action`, blocker and quiescence certificate. The adapter validates native role receipts, independent current-SHA QA/RV and CI through the native-cell runtime. CP cannot turn its own role string into a CO or fabricate a QA/RV pass. These are trusted local adapter checks, not cryptographic identity or a per-agent sandbox; inherited permissions still apply.

For active work, inspect the bound CO, resolve its next action (activate missing verification, return findings to the same IM, reconcile CI or recover proven stopped execution), then continue supervision. A blocked CO remains owned and points to a specific resolution. Readiness requires native LOCAL_REVIEW_READY at the exact current head plus a quiescent ownership certificate; summarize PR/SHA and independent evidence for owner local review. No merge action exists. If a head changes, fresh observations invalidate reuse; reacquire cap/ownership before continuing that same CO. Do not schedule recurring monitors unless the human requests them.

On restart load portable issue and CO state from durable GitHub/canonical artifacts, load private transport state, and reconcile fresh issue state, bound CO source and checkpoint digest with `rehydrate`. Missing/changed local bindings, receipts or GitHub head mean reconciliation work; never silently create replacements or accept stale readiness. Queue state is reconstructible only alongside actual issue/CO evidence, not from remembered status or transport handles alone. A durable checkpoint with an unresolved attempt resumes to `reconcile`, not to `activate`. Preserve unresolved native denials and bring one actionable human blocker only after safe recovery is exhausted.
